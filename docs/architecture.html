Document Ingestion, OCR Extraction, and Statutory Compliance Pipeline

Patra automates document sorting, layout OCR, and tax validation for accounting and CA firms. It ingests records from email, WhatsApp, and drive storage, validates GSTIN and PAN check digits, runs math reconciliation on line items, and tracks completion against audit and tax return checklists.

Core Architecture Details

Design choices and operational guarantees across the processing pipeline.

01
PP-StructureV3 GPU OCR

Standard OCR reads plain characters but discards table boundaries and multi-column hierarchy. Patra runs PaddlePaddle PP-StructureV3 on local RTX GPUs using CUDA 12.6. It recovers reading order and turns accounting tables into semantic HTML table elements.

  • › Spatial reconstruction keeps seller and buyer blocks in their original reading order.
  • › Converts multi-column transaction tables directly into HTML table structures.
  • › Caches OCR results on disk under backend/data/results/.
02
Dual LLM Providers with Failover

The pipeline uses Google Gemini 2.5 Flash as its primary provider because its 1M token context fits multi-page bank ledgers without manual chunking. If Gemini returns HTTP 429 or 5xx, the client switches to Groq (GPT-OSS-120B) with exponential backoff.

  • › Primary Gemini provider processes large bank ledgers in a single prompt.
  • › Groq fallback activates automatically when rate limits occur.
  • › Validates all JSON output with Pydantic models through up to three self-correction retries.
03
Multi-Taxpayer Family Segregation

Clients often upload mixed family documents in a single PDF. The segregation service scans pages for changing PAN and TAN values, splits the document into independent records, and attaches each file to the matching client member.

  • › Detects PAN, TAN, and taxpayer names across document pages.
  • › Splits bundles into sub-records linked to individual client member profiles.
  • › Prevents investment deductions and income items from leaking across taxpayer accounts.
04
DPDP Privacy and Statutory Checks

Before sending document text to external LLMs, the privacy layer masks the first eight digits of Aadhaar numbers (XXXX-XXXX-1234) and removes personal bank details to comply with India's DPDP Act 2023. The statutory engine then verifies the 15-character GSTIN Modulo-36 check digit.

  • › Redacts Aadhaar numbers locally before sending data to cloud APIs.
  • › Calculates the Modulo-36 check digit for 15-character Indian GSTINs.
  • › Verifies the 4th character of PAN strings matches the entity type (P, C, F, H).
05
Workflow State Machine and Delta Tracking

Active workflows track required versus received documents across audit and tax filing cycles. When an attached file passes validation, the delta engine marks the requirement complete. Once all mandatory items arrive, the workflow advances its state.

  • › Recomputes checklist completion when new files are attached.
  • › Advances status from collecting_documents to ready_for_review.
  • › Flags critical validation failures to pause automated progression.
06
Automated Follow-Up Reminders

The follow-up service drafts kickoff emails listing missing items with checkboxes. When deadlines approach, it suggests reminder channels based on days remaining: email for more than 15 days, WhatsApp and email for 7 days or fewer, and a phone call script for 3 days or fewer.

  • › Drafts personalized kickoff emails listing remaining checklist items.
  • › Escalates follow-up channels based on statutory filing deadlines.
  • › Generates talking points for staff when calling clients directly.
